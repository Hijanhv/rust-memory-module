Buffer overflow

A buffer has 5 slots. You write 6. The 6th byte lands on whatever happens to live next door.

In one sentenceA buffer overflow is writing past the end of a buffer, which silently overwrites the neighbouring memory.

The code

let mut buffer = [0u8; 5];        // 5 bytes on the stack
let not_in_buffer: u64 = 56789;   // a neighbour on the stack

unsafe {
    let ptr = buffer.as_mut_ptr();   // raw pointer to buffer[0]
    for i in 0..WRITES {
        *ptr.add(i) = i as u8;       // UB once i >= 5
    }
}
println!("not_in_buffer: {}", not_in_buffer);

ptr.add(i) means "the address i bytes after ptr". A raw pointer has no idea the buffer is only 5 long, so it never stops you.

The stack, byte by byte

On my Mac the program printed these addresses:

&buffer        = 0x16dd567d8
&not_in_buffer = 0x16dd567e0

That's 8 bytes apart. The buffer uses 5, then there are 3 bytes of padding (empty filler so the u64 starts at a tidy 8-byte boundary), then the 8 bytes of not_in_buffer. 56789 in hex is 0xDDD5, and Macs store the smallest byte first (little-endian), so its bytes are D5 DD 00 00 00 00 00 00.

The 6-write case is the important lesson: the program looked correct but had UB. Silent bugs are the worst kind.

What if you go further? (7, 10, 64...)

Think about what else lives on the stack near the buffer:

  • The loop counter i itself may be on the stack. Overwrite it, and the loop could restart or never end.
  • The return address: where the CPU jumps when the function finishes. Overwrite it and the program jumps to garbage and crashes, or worse, jumps where an attacker wants. This is the classic "stack smashing" attack.
  • Results can differ between cargo run and cargo run --release, because the optimiser lays out the stack differently. That's UB again: no promises.
Try it

Open lab/examples/08_buffer_overflow.rs, change const WRITES: usize = 6; to 9, then 12, then 64, and run:

cargo run --example 08_buffer_overflow

Why safe Rust can't do this

let mut buffer = [0u8; 5];
buffer[5] = 1;   // panics: index out of bounds: the len is 5 but the index is 5

Every index on an array, slice or Vec is bounds checked. Going out of bounds stops the program with a clear panic instead of quietly corrupting memory. A panic is a controlled stop. UB is chaos.
