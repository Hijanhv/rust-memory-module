Unsafe Rust: raw pointers and static mut

Lesson 2 breaks things on purpose using unsafe. Here's what the keyword actually allows, before we use it.

In one sentenceAn unsafe block lets you do five extra things the compiler can't check, and you become responsible for keeping them safe.
From the Rust Book: 20.1 Unsafe Rust.

Why unsafe exists

The compiler is careful: if it can't prove code is safe, it rejects it, even if the code is actually fine. Also, some jobs are unsafe by nature: talking directly to hardware, calling C code, or building low-level types like Vec. unsafe is the escape hatch for those.

The five superpowers

Inside unsafe { } you can:

  1. Dereference a raw pointer (follow it with *)
  2. Call an unsafe function
  3. Read or change a static mut
  4. Implement an unsafe trait
  5. Access fields of a union

Lesson 2 uses powers 1 (use-after-free, buffer overflow) and 3 (data race).

unsafe does NOT turn off the borrow checker or any other check. It only unlocks these five things. Everything else is still verified.

Raw pointers

A raw pointer is just an address with no promises attached:

Reference &TRaw pointer *const T / *mut T
Always points at a live valueMight point at freed memory, or nowhere
Borrow rules enforcedNo borrow rules: many *mut to the same thing is allowed
Never nullCan be null
Freed automatically? N/A (doesn't own)Doesn't own, never frees anything
let mut num = 5;

let r1 = &raw const num;      // making raw pointers is SAFE
let r2 = &raw mut num;        // (older style: &num as *const i32)

unsafe {
    println!("r1 is {}", *r1);  // FOLLOWING them needs unsafe
    *r2 = 10;
}

Creating a raw pointer can't hurt anything. It's just a number. Danger only starts when you follow it, so that's the part marked unsafe.

Raw pointer tools used in Lesson 2

let b = Box::new(5);
let p: *mut i32 = Box::into_raw(b);   // Box -> raw pointer. Rust stops freeing it for you.
let b2 = unsafe { Box::from_raw(p) }; // raw pointer -> Box. Rust will free it again.

let mut buf = [0u8; 5];
let ptr = buf.as_mut_ptr();           // raw pointer to buf[0]
unsafe { *ptr.add(2) = 9; }           // ptr.add(2) = address of buf[2]. No bounds check!

static mut

static mut COUNTER: u32 = 0;

fn add() {
    unsafe { COUNTER += 1; }       // every read or write of a static mut needs unsafe
}

Why unsafe? A static is visible to every thread. If two threads change it at the same time, that's a data race. The compiler can't prove you won't do that, so it makes you promise. (Modern Rust even warns about taking references to it. That's the #![allow(static_mut_refs)] line you'll see in Lesson 2.) In real code, use an atomic or a Mutex instead.

The golden rule

Keep unsafe blocks tiny, and wrap them in a safe function that checks everything first. That's how Vec is written. If something goes wrong, you know exactly which few lines to inspect.

Check yourself

Is creating a raw pointer unsafe?No. Only dereferencing it is.
Name two of the five unsafe superpowers.Any two of: dereference a raw pointer, call an unsafe fn, access a static mut, implement an unsafe trait, read union fields.
Does a raw pointer free memory when it goes out of scope?No. It owns nothing. That's why Box::into_raw without a matching Box::from_raw leaks memory.
Why does touching a static mut need unsafe?Any thread can access it, and the compiler can't prove there's no data race.
