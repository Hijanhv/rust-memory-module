Use-after-free

The heap gives a spot back to the allocator. You still have its address. You read it anyway.

In one sentenceUse-after-free is reading or writing heap memory after it was freed, when it may already belong to something else.

The plan

  1. Put a 5 in a Box on the heap.
  2. Turn the Box into a raw pointer, so Rust stops tracking it.
  3. Free the memory.
  4. Make a new Box. The allocator happily reuses the freed spot.
  5. Read through the old pointer.

What really happened on my Mac

$ cargo run --example 07_use_after_free
new Box lives at 0x102eb93b0, old pointer is 0x102eb93b0
value after free: 1234

Same address. The old pointer, which "should" hold 5, now reads 1234, a completely different value that belongs to y. No crash, no error message. In a real program that 1234 could be a password, or the old pointer could be used to write and corrupt y. That's how many real security holes work.

Could it crash instead?

The lesson asked you this. Connect it to Lesson 1:

  • Small freed blocks usually stay inside the allocator's pool. The page is still mapped to your process, so reading it is "allowed" by the MMU. No crash, just wrong data.
  • But if the allocator gives the whole page back to the OS (common for big allocations), the page is unmapped. Now the read hits a page you don't own, and you get a segfault.
  • So the hidden assumption behind "it won't crash" is: the allocator kept that page. That's not guaranteed by anything.

Why safe Rust can't do this

let x = Box::new(5);
drop(x);              // ownership moves into drop, memory freed
println!("{}", x);    // error[E0382]: borrow of moved value: `x`

Ownership means there's exactly one owner, and after a move the old name is dead. The compiler simply refuses. We needed Box::into_raw to escape ownership and get a pointer Rust doesn't track.

Check yourself

What does Box::into_raw do to ownership?It gives up the Box's ownership and returns a raw pointer. Rust will no longer free that memory for you or check how you use the pointer.
Why did the old pointer show 1234?The allocator reused the freed block for the new Box y. The old pointer and y now point at the same address.
Use-after-free is a ___ safety bug.Temporal (the "when" family). The address was valid, the object was dead.
