Rust Book essentials · Chapter 3

Variables, types, functions and loops

The everyday building blocks. Every example in Lectures 1 and 2 is made of these.

In one sentenceEvery Rust value has a type, and the type tells you exactly how many bytes it takes in memory.
From the Rust Book: 3.1 Variables, 3.2 Data types, 3.3 Functions, 3.5 Control flow. This page covers the parts you need.

1. Variables can't change unless you say so

let x = 5;
// x = 6;          // ERROR: cannot assign twice to immutable variable

let mut y = 5;     // mut = mutable = allowed to change
y = 6;             // fine

let z = 5;
let z = z + 1;     // "shadowing": a brand new variable that reuses the name. z is 6.

Rust makes things unchangeable by default because data that can't change can't be broken by surprise. You'll see this idea again with statics in Part 1.5.

2. Types = sizes

A bit is a single 0 or 1. A byte is 8 bits. Memory addresses point at bytes.

TypeWhat it holdsBytes
i8 i16 i32 i64 i128Whole numbers, can be negative1, 2, 4, 8, 16
u8 u16 u32 u64 u128Whole numbers, 0 or more (u = unsigned)1, 2, 4, 8, 16
usize / isizeSame size as an address. Used for indexes and lengths.8 on a 64-bit machine
f32 f64Decimals4, 8
booltrue / false1
charOne Unicode character like 'a' or '😀'4

If you don't write a type, Rust guesses. A whole number defaults to i32. That's why let x = 5; takes 4 bytes.

A u8 holds 0 to 255. That's why bytes are often written as two hex digits: 0x00 to 0xFF. You'll read hex a lot in Lecture 2.

Groups of values

let tup: (i32, f64, u8) = (500, 6.4, 1);   // tuple: fixed group, mixed types
let (a, b, c) = tup;                       // pull them apart
let first = tup.0;                         // or use .0 .1 .2

let arr: [u8; 5] = [0, 0, 0, 0, 0];        // array: fixed length, one type
let same = [0u8; 5];                       // shortcut: five zeros of type u8
let one = arr[0];                          // indexing starts at 0

[u8; 5] means "5 values of type u8". Its size is 5 × 1 = 5 bytes, known when compiling, so it lives on the stack. This is exactly the buffer in the buffer overflow lesson.

Arrays are bounds checked. arr[10] on a 5-item array doesn't read random memory, it panics (stops the program with an error message). The Book calls this "Rust's memory safety principles in action". Lecture 2 shows what happens when you skip the check with unsafe.

3. Functions

fn main() {
    let result = add_two(5);
    println!("{result}");       // prints 7
}

fn add_two(x: i32) -> i32 {     // every argument needs a type. -> i32 is the return type.
    x + 2                       // no semicolon = this is the value returned
}

Statements do something and end with ;. Expressions produce a value. The last expression in a function (no semicolon) is its return value. Add a ; after x + 2 and it stops being returned, and Rust will complain.

4. Loops

for i in 0..6 {        // 0, 1, 2, 3, 4, 5  (the 6 is NOT included)
    println!("{i}");
}
for i in 0..=6 { }     // ..= includes the end: 0 to 6

let mut n = 3;
while n != 0 { n -= 1; }

loop { break; }        // forever, until break

0..6 runs 6 times. That's why the buffer overflow example writes 6 bytes into a 5-byte buffer.

5. Printing (you'll use this constantly)

let x = 5;
println!("x is {}", x);    // normal
println!("x is {x}");      // same, shorter
println!("{:?}", [1, 2]);  // :? = debug print, works for arrays, Vecs, tuples
println!("{:p}", &x);      // :p = print as a memory address, like 0x16f86e724

Check yourself

How many bytes is [i32; 5]?5 × 4 = 20 bytes.
What type is let n = 7;?i32, the default for whole numbers.
How many times does for i in 0..6 run?6 times: i = 0, 1, 2, 3, 4, 5.
What does arr[9] do on a 5-item array in normal Rust?Panics with "index out of bounds". It never touches memory outside the array.
