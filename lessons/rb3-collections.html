Vec, String, Box and Drop

The heap types you'll meet in Part 1.4 and 1.5, and the cleanup system behind them.

In one sentenceVec, String and Box own memory on the heap, and their Drop code frees it automatically when they go out of scope.
From the Rust Book: 8.1 Vectors, 8.2 Strings, 15.1 Box, 15.3 Drop, 15.4 Rc.

Vec: a list that can grow

let mut v: Vec<i32> = Vec::new();   // empty
v.push(5);                           // add to the end
v.push(6);
let w = vec![1, 2, 3];               // vec! macro: create with values

let third: i32 = w[2];               // index: panics if out of range
let maybe: Option<&i32> = w.get(9);  // get: returns None instead of panicking

for x in &w { println!("{x}"); }     // loop over borrowed items

Vec<i32> reads as "a Vec of i32s". The <> holds the type of the items.

The Book's most important Vec example

let mut v = vec![1, 2, 3, 4, 5];
let first = &v[0];      // borrow the first item
v.push(6);              // ERROR: cannot borrow `v` as mutable because it is also borrowed
println!("{first}");

Why would pushing break a reference to item 0? The Book's answer: pushing might need a bigger heap block, so the items get copied somewhere new and the old block is freed. Then first would point at freed memory. That's a use-after-free, and the borrow rules catch it. You'll watch this reallocation happen in Part 1.4.

String: growable text

let mut s = String::new();
let s2 = String::from("hi");          // from a literal
let s3 = "hi".to_string();            // same thing
s.push_str("hello");                  // add text
s.push('!');                          // add one char
let both = format!("{s2} and {s3}");  // build a new String

Underneath, a String is a Vec<u8> of UTF-8 bytes. Same 3 numbers on the stack (pointer, length, capacity), letters on the heap.

You can't do s[0] on a String. Some characters take more than one byte (like é or 😀), so "byte 0" might be half a character. Rust refuses rather than give you garbage.

Box: put one value on the heap

let b = Box::new(5);     // the 5 is on the heap, b (a pointer) is on the stack
println!("{}", b);       // use it like the value: prints 5
println!("{}", *b + 1);  // * follows the pointer: 6

When to use a Box, according to the Book:

  • The size isn't known at compile time (e.g. recursive types, trait objects like Box<dyn Trait>).
  • You have a lot of data and want to move ownership without copying it all (only the 8-byte pointer moves).

Drop: the cleanup system

Any type can say what happens when it's cleaned up by implementing the Drop trait. Box, Vec and String use it to free their heap memory.

struct Noisy(&'static str);

impl Drop for Noisy {
    fn drop(&mut self) { println!("dropping {}", self.0); }
}

fn main() {
    let a = Noisy("a");
    let b = Noisy("b");
    println!("end of main");
}
// prints:
// end of main
// dropping b
// dropping a        <- reverse order of creation

You never call .drop() yourself. To clean up early use drop(x) (a normal function that takes ownership). You'll see drop(Box::from_raw(...)) in the use-after-free lesson: that's this.

Rc: when one owner isn't enough

use std::rc::Rc;
let a = Rc::new(5);
let b = Rc::clone(&a);   // doesn't copy the 5, adds 1 to a counter
println!("{}", Rc::strong_count(&a));   // 2

Rc = Reference Counted. It keeps a count of owners next to the value on the heap. When the count hits 0, the value is dropped. Rc only works on one thread. Its thread-safe twin is Arc (next page).

Check yourself

Why can't you push to a Vec while holding &v[0]?The push may move the items to a new heap block and free the old one, leaving your reference dangling.
What's the difference between v[9] and v.get(9)?v[9] panics if out of range. v.get(9) returns None.
In what order are values dropped at the end of a scope?Reverse order of creation: last created, first dropped.
Why can't you write s[0] on a String?Strings are UTF-8, and a character can be more than one byte, so byte 0 might not be a whole character.
