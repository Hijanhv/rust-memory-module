Wrap-up and a peek at Lecture 3

Lecture 3 is about how safe Rust makes every bug you just wrote impossible. Here's a head start.

In one sentenceOwnership, borrowing and lifetimes are the compiler's way of checking the memory safety rules from Lecture 2 before your program ever runs.

Bug → the safe Rust rule that stops it

BugRule that prevents itWhat you see instead
Use-after-freeOwnership: one owner, value dropped once, moved names are deadCompile error E0382 "borrow of moved value"
Dangling referenceLifetimes: a reference can't outlive the value it points toCompile error "returns a reference to data owned by the current function"
Buffer overflowBounds checks on every indexA clean panic at runtime
Data raceBorrowing: many & readers OR one &mut writer, never both. Plus Send/Sync for threads.Compile error

The borrowing rule is the data race rule

Look at the four data race conditions again. Borrowing says: at any moment, either many readers or exactly one writer. That makes condition 3 (someone writes while others access) impossible. Same idea, checked at compile time.

Try it: make the compiler say no

Open lab/examples/11_safe_rust_says_no.rs. Uncomment one block at a time and run:

cargo run --example 11_safe_rust_says_no

Read each error message slowly. Rust's errors explain exactly which rule you broke. Getting comfortable reading them is half of Lecture 3.
